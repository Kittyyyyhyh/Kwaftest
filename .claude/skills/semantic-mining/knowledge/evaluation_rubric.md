# 样本判定框架

## 核心问题

不只判"过了没有"。判的是：**这个样本能不能证明一个关于 WAF 能力的独立观点？**

一个 payload 打成功了但没有洞察价值——只是运气好撞上了一个未被覆盖的特定字符串——这不是好样本。一个好样本应该：
- 揭示了 WAF 的某个系统性缺陷
- 可以被泛化到其他类似场景
- 支撑一个关于 WAF 架构的独立见解

---

## 接入工作流

此文件在 Skill 的**第 3.2 步**（四维质量评估）被调用。执行前提：
- SKILL.md 第 1 步已完成（输出区域定位 + 基线响应已保存）
- SKILL.md 第 2 步已完成（边界展开，样本已产生 curl 响应）
- SKILL.md 第 3.1 步已完成（交叉验证，盲区稳定性已确认）

**判定流程**（在 Skill 第 3.2 步中执行）：

```
1. http_code == 403？ → 有效性=F → 记录拦截特征 → 结束
2. 定位输出区域（从第 1 步基线已知）→ 提取输出区域内文本
3. flag 在基线中已存在？ → false_positive
   flag 新出现在输出区域？ → data_extraction（有效性=S）
   flag 新出现在输出区域外？ → info_leak（有效性=A）
   响应与基线完全相同？ → no_effect（有效性=B）
4. AI 判断洞察性 → 归因到差异原语 → 交叉验证复现 → 评分
5. 判断可用性 → payload 长度/依赖/语法干净度 → 评分
6. 综合：有效性≥A + 洞察性≥A + 可用性≥A = ✅ 高质量样本 → 写入 batches/<run_id>.jsonl
```

## 四维质量模型

每个样本从四个维度独立评分，最终综合判定。

### 维度一：有效性 — 打成了没有？

| 等级 | 标准 | 标志 |
|------|------|------|
| **S — 完全成功** | 攻击意图完整达成，目标数据被提取 | flag 新出现在输出区域 |
| **A — 部分成功** | 攻击可执行但未拿到最终目标 | 输出区域出现 `uid=`、数据库错误中有表名 |
| **B — 仅绕过** | WAF 放了但什么实际效果都没 | 响应和基线一致 |
| **F — 被拦截** | WAF 拦了 | HTTP 403 或被拦页面 |

**场景特殊规则**：XSS 和 Log4j2 只能判到 B（WAF 层）。A 和 S 需要 OOB/浏览器确认。

### 维度二：危害性 — 达成了什么级别的攻击效果？

**危害层级**（从高到低）：

| 级别 | 名称 | 定义 | 示例 |
|:--:|------|------|------|
| **L5** | 任意代码执行 | 攻击者能执行任意系统命令/PHP代码 | CMDi 命令执行、Upload webshell 执行 |
| **L4** | 敏感数据窃取 | 读取了凭证/密钥/配置文件内容 | 读到 `/srv/app/config/credentials.env` 中的 API key |
| **L3** | 数据提取 | 从数据库中提取了非公开数据 | SQLi 读到其他用户的 api_token |
| **L2** | 信息泄露 | 暴露了系统/数据库结构信息 | SQL 错误泄漏表名列名、系统版本信息 |
| **L1** | 侦察确认 | 确认了漏洞存在但未提取数据 | `;id` 返回 `uid=33(www-data)`——知道命令可执行 |

**判定依据**：
- flag 本身代表了什么类型的凭证？（API key > 系统版本号 > 用户名）
- 提取这个数据能让攻击者做什么？（登录系统？访问内部 API？只是了解系统结构？）
- 这个危害是 payload 自身设计的还是意外副作用？

**注意**：危害级别不等于样本质量。一个 L1 的样本可以有很高的洞察价值（见维度三）。一个 L5 的样本如果只是碰巧撞上一个特定弱点，质量可能不如一个能证明系统性缺陷的 L2 样本。

### 维度三：洞察性 — 这个样本证明了什么？

**这是区分"运气好"和"真洞察"的关键维度。**

| 等级 | 名称 | 标准 |
|:--:|------|------|
| **S** | 系统性缺陷发现 | 揭示了 WAF 检测模型的**结构性缺陷**——不仅绕过了，还能解释 WAF 为什么在这个维度上注定会漏。可被泛化到其他命令/路径/场景。 |
| **A** | 边界精确定位 | 精确画出了 WAF 在某个维度的**能力边界**——"这个范围内 WAF 完全看不见"。不是偶然绕过，而是可预测的行为模式。 |
| **B** | 已知模式验证 | 验证了 WAF 在某个维度的已知行为，与 `crs_pl4_blindspots.md` 中的盲区吻合。没有新发现但确认了已知边界。 |
| **C** | 碰巧绕过 | 成功了但不知道为什么。或理由含糊——"可能是 WAF 不认识这个命令名"。无法解释为什么这个过得了而类似的过不了。 |
| **F** | 无洞察 | 被拦了，且被拦原因不明显。或 payload 失败且无法归因。 |

**S 级样本的特征**：
```
❌ C级: ";dd if=/srv/data/db.json 绕过WAF" 
        → 为什么 dd 能过而 cat 不能？不知道。可能明天 WAF 加规则就拦了。

✅ S级: "WAF的命令检测基于黑名单(932160)，不是基于文件读取行为。
        黑名单外有12+个命令能读文件(dd/tee/cut/sort/tr/file/awk/sed/...)。
        WAF无法穷举所有文件读取命令——这是基于黑名单的检测模型的先天缺陷。
        这个盲区不是某个命令的缺失，而是整个检测范式的盲区。"
```

**S 级样本在答辩中能讲出完整故事**："我发现 CRS 的检测逻辑是 X，但 shell 的执行逻辑是 Y。X 和 Y 之间的 gap 是结构性的，不是某个规则写漏了——WAF 的整个检测模型在这个维度上存在先天盲区。"

### 维度四：可用性 — 实战中能不能用？

| 等级 | 标准 |
|:--:|------|
| **S** | Payload < 100 字符，无版本/配置依赖，语法干净。用最简洁的方式表达了攻击意图。 |
| **A** | Payload < 200 字符，有轻微依赖（如需要特定 MySQL 版本），但总体干净。 |
| **B** | Payload > 200 字符或较复杂，但仍可稳定运行。 |
| **C** | 有语法瑕疵、需要特定条件（特定 PHP 配置/MySQL sql_mode），或输出不完整。 |
| **F** | 语法错误、巧合返回 200 但实际未执行。废弃。 |

## 综合判定

### 高质量样本（入库，答辩可用）

```
有效性 ≥ A  +  洞察性 ≥ A  +  可用性 ≥ A
```
缺一个维度就降级。一个 payload 打得漂亮但说不出为什么 → 洞察性 C → 不是高质量样本。

### 答辩叙事样本（特别标记）

```
洞察性 = S  +  有效性 ≥ A
```
这些样本不一定是打得最深的，但能支撑一个关于 WAF 能力的独立观点。答辩时用它们来讲故事。

### 边界标记（不产出样本，但写入注意力地图）

```
有效性 = F（被拦）→ 用于画 WAF 有效覆盖的边界
```
告诉 AI "这个方向 WAF 守住了，别在这浪费轮次"。

### 废物

```
有效性 = B（只绕过无效果）→ 废弃
有效性 ≥ A + 可用性 = F（语法错误）→ 废弃
有效性 ≥ A + 洞察性 = C + 可用性 = C → 废弃（过了但说不清为什么，质量也差）
```

## 场景特殊处理

| 场景 | 有效性天花板 | 原因 |
|------|:--:|------|
| CMDi | S | curl 可完整验证命令执行 + 数据提取 |
| SQLi | S | curl 可完整验证查询结果 |
| Upload | S | curl 可验证上传 + webshell 执行 |
| XSS | B | curl 只能判 WAF 是否拦截。A 和 S 需浏览器验证 |
| Log4j2 | B | curl 只能判 WAF 是否拦截。A 和 S 需 OOB 服务器确认 |

XSS 和 Log4j2 的 WAF 通过样本标注 `pending_verification`。不作为高质量样本入库——但可以作为"边界标记"证明 WAF 在某个维度放了行。

## 执行中的判定流程

每条样本 curl 后：

```
1. http_code == 403？ → 有效性=F。记录拦截特征。结束。

2. 定位输出区域（从基线已知）→ 提取输出区域内文本。

3. 输出区域内含新信息？
   ├── 含 flag 且基线中没有 → 有效性=S（数据提取）
   ├── 含系统信息但无 flag → 有效性=A（信息泄露/命令可执行）
   ├── 含其他新内容但不敏感 → 有效性=B（仅绕过无效果）
   └── 和基线一致 → 有效性=B（无效果）

4. AI 判断洞察性（基于差异原语归因）：
   "这个 payload 利用了哪个解析器差异？"
   "这个差异是 WAF 检测模型的系统性缺陷，还是碰巧绕过了一个特定规则？"
   "换一个类似的 payload 能否复现这个绕过效果？"
   → 如果无法回答 → 洞察性=C（碰巧绕过）
   → 交叉验证（换维度值重测一次）→ 一致成功 → 洞察性≥A

5. 判断可用性：
   - payload 长度 < 200？语法是否干净？有无特殊依赖？
   → S/A/B/C

6. 综合判定：
   有效性≥A + 洞察性≥A + 可用性≥A = ✅ 高质量样本
```

**AI 在判定中的不可替代价值**：
- 正则无法区分"页面模板中的 flag"和"命令输出中的 flag"
- 正则无法判定"这个绕过是系统性的还是碰巧的"
- 正则无法判断 payload 的实战可用性
- **只有 AI 能做洞察性判定**——这是 Skill 的核心智识贡献
