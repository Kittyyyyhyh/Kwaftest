## 架构决策记录 (ADR)

### ADR-01: WAF 选型
- **决策**: 使用 `owasp/modsecurity-crs:apache` 官方镜像
- **原因**: OWASP 官方维护，CRS 规则最完整，PL4 一键切换，答辩有说服力
- **备选方案**: Coraza (Go实现) — 规则兼容性非100%，放弃；Nginx+ModSecurity v3 — 编译复杂，放弃

### ADR-02: WAF 与 App 分离
- **决策**: WAF 作为独立反向代理容器，App 容器不内置任何防御逻辑
- **原因**: 对齐 CLAUDE.md "靶场只承载原始语义攻击，不内置编码逻辑"

### ADR-03: 靶场关卡设计
- **决策**: 每关差异在于注入上下文（数字型/字符型/LIKE/ORDER BY/盲注），而非靶场防御递增
- **原因**: 靶场零防御，所有难度来自 WAF；不同 SQL 上下文对 WAF 检测能力的考验不同

### ADR-04: 攻击反馈机制
- **决策**: 使用 WAF 审计日志 (audit.log) + 响应头 + CSV 样本记录三层反馈
- **原因**: curl 手动测试看响应头，批量测试看 CSV，报告生成解析 audit.log

### ADR-05: API 设计
- **决策**: 提供 POST /api/attack.php 供 AI 批量调用，不在靶场内置 Web 攻击面板
- **原因**: 用户倾向手动 curl 注入，AI 批量攻击走 API，保持灵活性

### Step 3: WAF 配置 ✅

文件: `waf/custom-rules.conf`

配置内容:
- `SecAuditEngine On` — 开启审计日志
- `SecAuditLogParts ABCEFHZ` — 详细日志级别
- `SecRule` 在 403 响应时设置环境变量标记

## 遇到的问题及解决方案

### 问题1: Docker Hub 网络不可达
- **现象**: `docker pull php:8.2-apache` 超时
- **原因**: 国内网络限制，Docker Hub 被墙
- **解决**: 
  1. 修改 `~/.docker/daemon.json` 添加国内镜像源 (DaoCloud, timeweb.cloud, Tencent Cloud)
  2. 使用完整镜像URL直接拉取: `docker pull docker.m.daocloud.io/library/php:8.2-apache`
  3. 拉取后 tag 为短名: `docker tag docker.m.daocloud.io/library/php:8.2-apache php:8.2-apache`
  4. **注意**: daemon.json 配置需重启 Docker Desktop 才能对 `docker pull` 短名生效

### 问题2: WAF 容器端口映射错误
- **现象**: curl localhost:8000 返回 "Empty reply from server"
- **原因**: owasp/modsecurity-crs 镜像以非 root 运行，Apache 监听 8080 而非 80
- **解决**: docker-compose 端口映射改为 `8090:8080`，添加 `PORT: "8080"` 环境变量

### 问题3: DaoCloud 镜像不支持第三方命名空间
- **现象**: `docker pull docker.m.daocloud.io/owasp/modsecurity-crs:apache` 返回 403
- **原因**: DaoCloud 仅镜像 Docker Hub 官方 library，不支持 `owasp/` 命名空间
- **解决**: 使用 timeweb.cloud 镜像 (`dockerhub.timeweb.cloud/owasp/modsecurity-crs:apache`)
